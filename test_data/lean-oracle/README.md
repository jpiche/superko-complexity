# Lean oracle fixtures

**Author:** Joseph J. Piché
**Models:** Claude Opus 5 (`claude-opus-5`)

Tables evaluated from the Lean development and replayed against the Rust
mirror by [`../../crates/superko-rules/tests/lean_oracle.rs`](../../crates/superko-rules/tests/lean_oracle.rs).
Generated by [`../../tools/gen-oracle.sh`](../../tools/gen-oracle.sh) from
[`../../lean/Oracle.lean`](../../lean/Oracle.lean); the hashes each file
records are held against the working tree by
[`../../tools/check-oracle.sh`](../../tools/check-oracle.sh).

These are neither literature fixtures nor project fixtures in the sense of
[`../README.md`](../README.md). They are a second *reading* of the same
definitions, which is why what they establish is narrow, and stated below
before the format is.

## Grade: `observed`

Every row was produced by the Lean **compiler**, through the interpreter that
`lean --run` starts — the trust surface `native_decide` has, not the kernel's.
No row is backed by a proof. **No row supports a ledger entry**, and none is
cited by one.

The upgrade that would change this is a `decide`-proved digest theorem per
table, a `kernel-checked` grade. Its feasibility at these board sizes is
unmeasured, and the cost figures below are not encouraging.

## What agreement establishes, and what it does not

Every value comes from the computable twins — `resolve'`, `PlayableAt'`,
`area'`, `afterC`, `step'`, `start'`, `SSK'`, `PSK'` — and each of those is
tied to the `Defs.lean` item it computes by a bridge lemma the kernel has
checked (`resolve'_eq_resolve`, `playableAt'_iff`, `area'_eq_area`,
`afterC_eq_after`, `step'_toState`, `start'_toState`, `ssk'_faithful`,
`psk'_faithful`). So a row is about the audit target and not about a
restatement convenient to Rust, and a green test run is `computed` evidence
that the mirror computes what the Lean computes, on the rows covered.

It is not evidence that:

- **the definitions describe Go.** Both sides read the same definitions. That
  question is the independent-agreement argument of
  [`../../docs/trusted-base.md`](../../docs/trusted-base.md), which needs a
  number someone else computed — the 2x2 count under positional superko — and
  which these files do not touch.
- **anything holds off the fixture boards.** Coverage stops at `m * n ≤ 6`.
- **the game tree agrees past the trace depth.** The `play` traces are cut at
  the depth in each file's `# play-depth:` header, which is as low as 0 on the
  six-point boards.
- **any count beyond the two-point boards agrees.** Only `1x1`, `1x2` and
  `2x1` carry a `count` row; see the cost note.

What the traces do reach, on the boards where they run deep enough, is the
repetition clause itself rather than only the board conditions: 16 rows on
`1x2` and 14 on `1x3` are refusals at a point that is empty and whose chain
would breathe, so the archive is what refused them; and on `1x3` and `3x1`
there are two rows where `SSK'` and `PSK'` return different verdicts at the
same state and move. Without those the traces would pin the board mechanics
twice over and the two rules not at all.

Suicide is forbidden throughout, because that is `Defs.lean`'s rule. The
crate's `Suicide::RemoveOwn` has no Lean counterpart, so no row here could be
about it.

## Format

Line-oriented and whitespace-separated. `#` opens a header line; the header
carries the format marker `# superko-oracle 1`, the board, the toolchain, the
SHA-256 of `Defs.lean`, `Basic.lean` and `Decide.lean`, the grade, the trace
depth and the command that produced the file.

A position crosses this boundary as its rows over `.`, `X` (black) and `O`
(white), row-major, separated by `/` — never as a position code, which is
meaningless without the convention that produced it. Points are `row,col`,
zero-based. Colors are `b` and `w`. Moves are `pass` or `row,col`.

Positions are enumerated in base-3 code order over **all** `3 ^ (m * n)`
positions, legal and illegal alike: digit `row * n + col`, 0 empty, 1 black,
2 white.

| Row | Fields |
|---|---|
| `resolve` | position, color, point, the position after that color plays there |
| `playable` | position, color, point, `1` when the point is empty, `1` when the played chain has a liberty |
| `area` | position, Black's area, White's area |
| `play` | rule, depth, path, position, color to move, move, verdict, passes, archive size |
| `count` | rule, games from the empty board |

`resolve` is defined at occupied points too, because `Superko.resolve` is
total there; whether the play is *allowed* is the separate `playable` row.
`playable` emits its two conjuncts apart, so that a mirror refusing the right
moves for the wrong reason is caught rather than cancelled out.

A `play` row's `path` is the move sequence from the root of play,
`;`-separated, or `root` at the root. The traces walk every legal line to the
file's depth; a state where the game has ended contributes its own row and is
not continued. Read together they pin the root seeding of `start'`, the
insertion `step'` performs on a pass, and the pass exemption both rules carry.

## Cost, measured

The reason the `play` and `count` tables thin out as the board grows. Walking
the game tree through the computable rules, in the Lean interpreter, costs
roughly ten to twenty times more per extra ply, and the constant grows with
the board. Measured on this toolchain (`observed`, wall clock, whole file):

| board | play depth | cost |
|---|---|---|
| 1x3 | 4 | 23 s |
| 1x3 | 6 | about 8 minutes per rule |
| 1x4 | 2 | 18 s |
| 1x4 | 3 | 300 s |
| 1x5 | 0 | 20 s |
| 1x6 | 0 | 279 s |
| 2x3 | 0 | 340 s |

`docs/plans/rules-mirror-plan.md` asks for six plies at `m * n ≤ 3` and four
above; the measurement is what the depths are set from instead, and each file
records the figure it was produced at.

The `count` table stops at two points for the same reason. A game on the 1x3
board runs to twenty-one plies (`computed`, by the Rust mirror: 907 games and
2721 nodes under PSK, 959 and 2877 under SSK), and the Lean walk does not
reach that depth at any figure this project was willing to wait for. A
depth-capped number is not a count of games and is not offered as one.

The `resolve`, `playable` and `area` tables are complete on every board:
every position, both colors, every point. They are the bulk of the file and
the part a mirror is likeliest to get wrong.

## Regenerating

```sh
tools/gen-oracle.sh            # every board with m * n <= 6, about half an hour
tools/gen-oracle.sh 2x2        # one board
tools/check-oracle.sh          # hashes still match the working tree
cargo test -p superko-rules --test lean_oracle
```

A change to `Defs.lean`, `Basic.lean` or `Decide.lean` invalidates every
fixture, and `check-oracle.sh` fails until they are regenerated. That is the
point of recording the hashes: a fixture that outlived the definition it was
generated from would be a test passing against a definition that no longer
exists.
