# C-32 — the machine step of the archive argument

**This file is the proof. It is not machine-checked, and no source proves it.**
The claim's ledger status is `folklore`, and this file exists so that the
sentence the status attaches to is written out in full rather than gestured
at as "the archive argument".

## The claim

> A deterministic Turing machine that decodes the input, iterates the archive
> decider's step from the initial configuration, and reads off the verdict
> uses work space polynomial in the configuration size, uniformly in the
> board dimensions. With C-30 and C-31, the language SUPERKO-GO therefore lies
> in SPACE(2^O(|w|)) ⊆ EXPSPACE, in the sense of Hearn 2006, Appendix A.

`|w|` is the length of the input string under the encoding of C-31.

## What is proved, and where

Everything on the far side of the one sentence is a kernel-checked theorem
about `Defs.lean`:

- **The decider decides the game.** `Superko.C29_decideWins_iff_blackWins`
  (C-29): run at `⌊komi⌋` with fuel `4·3^(m·n) + 1`, the fuel-indexed archive
  decider returns `true` exactly when `Superko.BlackWins m n b komi` holds.
  The fuel is C-26's game-length bound.
- **The input is honest.** `Superko.Enc.C31_enc_length_lower` (C-31):
  `2·m·n ≤ |enc|`, so `3^(m·n)` is singly exponential in `|w|`;
  `card_situation_le_two_pow_length` and `lengthBound_le_two_pow` restate
  the situation count and the game-length bound in terms of `|w|`.
- **Every komi is an ordinary input.** `Superko.C27_blackWins_iff_halfInteger`
  (C-27): the verdict depends on komi only through its floor, so the one
  rational comparison in the leaf is a comparison of integers of
  `O(log |w|)` bits once the input is decoded.

Still open on the proved side, and recorded as such:

- **C-30, the run-level configuration bound.** A static bound on one
  configuration of the decider's state exists in scratch. The theorem this
  sentence consumes — that every configuration an explicit small-step machine
  reaches from the initial one fits in `2^O(m·n)` bits, with the archive
  shared along the search path — is not written. Until it is, the space
  account below rests on the per-frame bound of the big-step decider, which
  is still `2^O(m·n)` with a larger constant in the exponent.

## The sentence, and what it rests on

The decider's step does four kinds of work on a configuration: a legality
check (an empty point, a liberty test, a membership test of a situation
against the archive), a board update, a pass-counter update, and at a leaf one
integer comparison. Each is a computation on first-order data whose size is
bounded by the configuration's, and each is implementable on a random-access
machine in space polynomial in that size. The liberty test as promoted routes
through Mathlib's decidable graph reachability, which materializes walk sets;
that is polynomial in the configuration size, which is all this sentence
needs, and it would not be polynomial in `m·n` per step, which nothing here
claims.

The steps of that sentence, with the status each carries:

| Step | Status | Source |
|---|---|---|
| A Lean-defined step function on first-order data is a sequential algorithm in the sense of the invariance literature | asserted by inspection | no source proves this for a Lean function |
| A sequential algorithm with configuration size `S` runs on an arithmetic random-access machine in space `O(S)` | `cited` | Dershowitz and Falkovich-Derzhavetz 2015, Theorem 2 (the space invariance theorem), for an arithmetic RAM whose word grows to `O(log S)` |
| RAM space `S` is Turing-machine space polynomial in `S` | covered by no source read | Cook and Reckhow 1973, Theorem 2, is time-only; Slot and van Emde Boas 1984 and 1988, and van Emde Boas 1990, are unread by this project |
| SPACE(2^O(n)) ⊆ ⋃ₖ SPACE(2^(n^k)) = EXPSPACE | definitional | Hearn 2006, Appendix A.4 |
| The k-tape and one-tape space classes coincide at these bounds, if the prose is ever stated for one-tape machines | `folklore` | Hearn 2006 asserts it without citation; avoided by stating the bound for multitape machines |

The whole sentence is the content of Saffidine, Teytaud and Yen 2015,
Theorem 1, which its authors label a folklore result and prove in one line by
depth-first search over an exponential representation. This project's
contribution is to have moved the correctness of that search, and the
arithmetic of the exponential representation, onto the machine-checked side.
The instantiation of the invariance thesis to this project's own functions is
asserted here by inspection, in those words.

## Why the sentence is not a theorem here

A class membership is a statement about Turing machines, and there is no
Turing machine in `lean/`. That is a decision, recorded in
[`../docs/plans/complexity-grounding.md`](../docs/plans/complexity-grounding.md):
every Lean library that defines the class would put its own definitions into
the trusted base, none proves that its class is the textbook's, and the
alternative of a hypothesis-carrying theorem is vacuous in the form that
avoids a machine model. Experiment 003 is the pre-registered attempt to
obtain a second, machine-checked witness in a disclosed side base; nothing
here depends on its outcome.

## What would change this file

- Obtaining Slot and van Emde Boas, or van Emde Boas 1990, and finding the
  RAM-space-to-TM-space step proved there narrows the residue to the first row
  of the table alone.
- Obtaining Robson 1984 or 1985 and finding that its no-repeat result covers
  situational superko on the time-exponential branch makes C-3 `cited`; this
  file then documents a corroboration rather than the only route.
- Proving C-30 removes the per-frame caveat above.
